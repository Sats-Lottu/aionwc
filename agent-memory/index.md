# aionwc project memory

- Sats-Lottu maintains the package. The request flow and cryptographic primitives are based on eddieoz's `nwc-agent/scripts/nwc_wallet.py`. The sole required Python dependency is `websockets`.
- NIP-04 uses OpenSSL AES-256-CBC by default. The `nip04-fallback` extra installs `pyaes` for platforms without working OpenSSL AES. NIP-44 works independently of AES.
- secp256k1 prefers the system `libsecp256k1` for ECDH and Schnorr. OpenSSL handles curve operations when detected, with Python arithmetic available as the portability fallback. Verified native selection with OpenSSL 4 on Windows and libsecp256k1 0.5 on Debian.
- Relay fallback ends at the first publication attempt. The wallet may have processed a payment even if the client timed out or the WebSocket disconnected.
- The optional HTTP payment API uses L402 macaroons, MPP Lightning `charge`, and x402 v2 `exact` on `lnbtc` with `http:1` request binding. The FastAPI extra includes the payer and receiver. The user requires application-owned persistence. `PaymentServer` accepts a `PaymentStore` interface with async `save`, `get`, and atomic `consume` operations implemented by the application. See [[README#HTTP payments|HTTP payments]] for the usage guide.
- HTTP 402 detection defaults to L402/LSAT, MPP, then x402 headers. The user requires configurable priority. `PaymentClient(protocol_order=...)` accepts a nonempty sequence of unique protocol names, snapshots it, and limits automatic detection to those names. An `l402` JSON body is a fallback after headers when `l402` is included. The body uses the same invoice checks and budget limit. `PaymentClient.challenge(response).protocol` inspects the result without paying.
- The user prefers adapting `nwc-agent` over adding the `bolt11` package. The internal BOLT11 decoder adapts `scripts/nwc_bolt11.py`, corrects amount and numeric-field handling, and validates/reconstructs the ECDSA signing key using existing secp256k1 arithmetic. Official invoice vectors are kept under `tests/data/` with source attribution in the tests.
- On 2026-11-17, `poetry run pytest -o addopts= --cov=aionwc --cov-report=term-missing --cov-report=html --cov-fail-under=100 -q --tb=short` passed all 298 tests on Windows / Python 3.12.10, including four Docker integrations, with 100% line coverage across all 1,353 executable source lines. Native API failures and platform discovery use controlled doubles; reference vectors and local WebSocket/ASGI flows also run. The HTML report is generated under `htmlcov/`. The default selection runs 294 tests without Docker; `pytest -m integration` selects the four Docker cases. An earlier 97-test run passed with imports of `bolt11`, `bitstring`, `bitarray`, `coincurve`, `bech32`, `base58`, and `tibs` blocked.
- Regression tests cover malformed FastAPI query strings and raw request targets. URL construction belongs inside the dependency's validation block so decoding errors produce HTTP 400 before the wallet is called.
- The Docker integration uses LNbits 1.7.1, NWC Provider 1.2.1, nostr-rs-relay 0.9.0, and LNbits' `FakeWallet` funding source. Each test receives fresh NWC wallet pairs while the module shares the containers. The four cases verify the NWC invoice lifecycle and FastAPI payment round trips for L402, MPP, and x402: automatic detection, cryptographically valid preimages, settlement, balances, receipts, request binding, and replay behavior. Wallet calls use the actual NWC provider and relay; Lightning routing outside LNbits is outside this fixture.
- Docker can change an ephemeral host port when LNbits restarts. Refresh the HTTP client's base URL after restarting the provider, using `get_exposed_port(5000)`, before registering test wallets.
- `publish.yml` runs Docker integration on pull requests, manual runs, and releases. Publishing depends on both the build (with 100% line coverage required) and integration jobs. The edited workflow passed `rhysd/actionlint:1.7.12` in Docker, and `poetry check --lock --strict` passed locally.
- The Windows OpenSSL path passed all 19 official BIP340 vectors. The Python fallback passed the in-repository BIP340 and NIP-44 reference cases and uses variable-time arithmetic.
- [[README#Development|Development commands]] cover package builds, test selection and the on-demand `pytest-cov` report. Windows sandbox runs need access to Docker Desktop and loopback for the integration test.
- Documentation uses Sphinx autodoc and Furo in the optional Poetry `docs` group. Build with `poetry run sphinx-build -M html docs docs/_build -W --keep-going`. [Read the Docs Community](https://aionwc.readthedocs.io/) hosts the public site, and package metadata links to it starting with version 0.1.1.
- README branding uses the transparent violet ImageGen logo in `docs/_static/aionwc-logo.png`, with its generation prompt alongside it. The symbol is a prominent Lightning bolt inside a thin circular orbit with two arrowheads, following the user's request for a clearer symbol. The README references the GitHub-hosted asset for PyPI rendering and uses live PyPI, GitHub Actions, and Read the Docs badges. HTTP payment examples require the `payments` or `fastapi` extras introduced in version 0.2.0.
- The Quickstart documents installation as a dependency from PyPI or a built wheel. Source checkout commands belong in the development guide.
- Version 0.1.0 was published to PyPI. GitHub Releases publish through `publish.yml` with the `pypi` environment. Trusted Publishing and the validation procedure are documented in `.github/RELEASING.md`.
